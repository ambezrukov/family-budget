# Бот учёта семейных расходов

Телеграм-бот на Google Apps Script: принимает расходы текстом, голосом, фото
чеков и ссылками на цифровые чеки из SMS, разбирает, категоризирует и
складывает в Google-таблицу.

Работает целиком на бесплатных сервисах: Apps Script + Google Sheets +
Telegram Bot API + бесплатный уровень Gemini API. Своего сервера не требует.

**Как поставить себе — [УСТАНОВКА.md](УСТАНОВКА.md)**: пошаговая инструкция на
30–40 минут, программировать не придётся. Та же инструкция страницей с
галочками «шаг сделан» — [ustanovka.html](ustanovka.html).

Проект сделан для одной семьи и выложен как есть: берите, ставьте себе,
меняйте под себя (лицензия MIT). Ничего общего с моей установкой у вашей не
будет — своя таблица, свой бот, свои ключи.

Техническое задание, по которому всё сделано — [promt-bot-rashody.md](promt-bot-rashody.md).

## Что умеет

| Ввод | Как обрабатывается |
|---|---|
| **Текст** — «250 продукты, 80 бензин и 45 аптека» | Gemini: список трат, суммы, валюты, даты, категории |
| **Голос** — русский, иврит, смешанный | один запрос к Gemini Flash: расшифровка и разбор в JSON сразу |
| **Фото чека** — включая ивритские | Gemini Flash: итог из строки итога, дата с чека, магазин, позиции |
| **Ссылка на чек** — пересланная SMS магазина | известные сервисы отдают чек готовыми данными; остальное читается как PDF, картинка или текст страницы |
| **Доход** — «+12000 зарплата» | плюс перед суммой отправляет запись в лист «Доходы», минуя разбор смысла |

Текст и голос возвращают **список** трат: в одном сообщении их может быть
несколько. Дальше — запись в таблицу и одна общая сводка с кнопками
«Изменить категорию» / «Удалить» на каждую трату.

Если модель недоступна (сбой или дневной лимит), текст разбирает локальный
парсер, а категорию подбирает словарь ключевых слов — расход не теряется.

**Доходы и расходы разведены по разным листам.** Доход помечается плюсом
(«+12000 зарплата») — это правило железное и модели не доверяется; слова
«зарплата», «аванс», «премия» модель узнаёт и сама, но тогда в ответе прямо
написано «Записал доход» и висит кнопка «Это расход», переносящая запись между
листами. Возврат денег за товар — не доход, а минусовая строка в той же
категории расходов. Снятие наличных и переводы друг другу не записываются
вовсе: деньги переложены, а не потрачены.

Отдельно: сводки по командам, месячный отчёт по триггеру, белый список
пользователей, лог всего, что не разобралось.

## Устройство

```
src/
  appsscript.json   манифест: часовой пояс, права, веб-приложение
  00_Config.gs      константы, секреты из свойств скрипта, лист «Настройки»
  01_Sheets.gs      вся работа с таблицей: запись, чтение, категории, лог
  02_Telegram.gs    транспорт Bot API: сообщения, кнопки, скачивание файлов
  03_Gemini.gs      вызовы модели со строгими JSON-схемами и повторами
  04_TextParser.gs  запасной разбор текста без модели: сумма, валюта, дата
  05_Categorizer.gs категоризация без модели: словарь ключевых слов
  06_Reports.gs     сводки и месячный отчёт
  07_State.gs       защита от повторов и незавершённые записи
  08_Handlers.gs    логика общения: сообщения, чеки, голос, кнопки
  09_Main.gs        doPost — точка входа вебхука
  10_Setup.gs       первичная настройка, стартовые категории, самопроверка

  11_Polling.gs     запасной приём сообщений опросом, без вебхука
  12_Links.gs       чек по ссылке из SMS: сервисы цифровых чеков, PDF, страницы
  13_MiniApp.gs     мини-приложение телеграма (необязательное, см. ниже)
  14_Updates.gs     проверка новых версий и обновление по кнопке

proxy/              посредник между Telegram и Apps Script (Vercel)
dist/               весь код, склеенный в один файл — на случай ручной
                    установки без clasp (node tools/build.js)
tools/build.js      сборщик dist/
tools/deploy.js     выкатка: тесты → сборка → clasp push → версия → развёртывание
tests/              локальные проверки на Node (см. ниже)
```

**Выкатка правок — одна команда:**

```bash
node tools/deploy.js
```

Она прогоняет тесты, пересобирает `dist/`, заливает код через `clasp` и —
обязательно — создаёт новую версию и обновляет развёртывание.

Последний шаг легко забыть, а он критичен: вебхук исполняет **развёрнутую**
версию, а не последнюю сохранённую. Без обновления развёртывания бот
продолжит работать по старому коду, хотя в редакторе будет виден новый.

Проверить, что в облако поедет именно рабочий код, можно и отдельно:
`BUNDLE=1 node tests/test_integration.js` — тот же набор проверок, но против
собранного `dist/Код.gs`.

## Как сообщения доходят до скрипта

Тут пришлось повозиться, и результат неочевиден.

**Прямой вебхук на Apps Script не работает.** Веб-приложение Apps Script на
любой запрос — и GET, и POST — отвечает перенаправлением (302) на
`script.googleusercontent.com`. Браузер за ним идёт, а Telegram нет: он считает
такой ответ ошибкой и пишет `Wrong response from the webhook: 302 Found`,
сообщения копятся в очереди. Настройками развёртывания это не лечится —
проверено на свежесозданном развёртывании с доступом «Все».

Поэтому есть два рабочих способа, оба реализованы:

**Вебхук через посредника** (используется сейчас). Крошечная функция на Vercel
(`proxy/api/telegram.js`) принимает POST от телеграма, проверяет подпись и
передаёт запрос в Apps Script, спокойно проходя перенаправление. Сообщения
приходят мгновенно. Телеграм подписывает запросы секретным словом
(`secret_token`), посредник его проверяет, а для Apps Script добавляет тот же
секрет параметром `?s=` — код проверяет его в `doPost`.

Что где лежит:

| Значение | Где хранится |
|---|---|
| Адрес посредника | свойство скрипта `WEBHOOK_URL` |
| Секретное слово | свойство скрипта `WEBHOOK_SECRET` и переменная Vercel `WEBHOOK_SECRET` |
| Адрес Apps Script | переменная Vercel `APPS_SCRIPT_URL` |

**Опрос по таймеру** (запасной путь, `11_Polling.gs`). Триггер раз в минуту
вызывает `pollUpdates`, тот забирает накопившееся через `getUpdates`. Внешних
сервисов не нужно вовсе, но ответ приходит с задержкой до минуты, и опрос
съедает около трети суточной квоты триггеров (1440 запусков).

Переключение — одной функцией в любую сторону: `switchToWebhook` /
`switchToPolling`. Если Vercel однажды отвалится, второе вернёт бота к жизни
без правки кода.

Файлы пронумерованы только для удобства чтения — Apps Script загружает их все
разом, порядок значения не имеет.

### Хранилище

Одна Google-таблица, семь листов:

- **Расходы** — 17 столбцов: от даты создания до признака удаления и служебного
  ID (по нему кнопки находят свою строку, даже если строки двигали руками).
- **Доходы** — та же структура, заполняется при вводе с плюсом.
- **Категории** — справочник с ключевыми словами, правится руками.
- **Категории доходов** — отдельный справочник: зарплата, фриланс, подарки,
  проценты. Свой, потому что слова у доходов и расходов разные.
- **Настройки** — базовая валюта, курсы, белый список, чат отчёта, модели.
- **Лог** — ошибки, нераспознанное, сырые ответы модели при сбоях.

### Принципы, заложенные в код

**Запись не теряется.** Если модель не ответила, вернула мусор или упёрлась в
лимит — расход всё равно сохраняется с категорией «Без категории», а причина
уходит в лист «Лог».

**Без подтверждения ничего не пишется.** Не читается итог чека — бот
переспрашивает и держит черновик, а не записывает угаданное. Если в сообщении
несколько трат и хотя бы у одной нет суммы, не пишется **ни одна** из них:
недостающие суммы бот спрашивает по очереди и сохраняет всё разом.

**Удаление — мягкое.** Строка помечается, а не стирается. Сводки и отчёты
удалённые игнорируют.

**Секреты не в коде.** Токен бота, ключ Gemini и идентификатор таблицы лежат в
свойствах скрипта. Ссылка на файл в таблице хранится как `tg:<file_id>`, а не
прямым URL — прямой адрес телеграма содержит токен бота.

**Посторонним бот не отвечает вообще.** Ни на сообщения, ни на команды, ни на
кнопки — снаружи он выглядит неживым. Попытка пишется в лист «Лог» вместе с
телеграм-айди отправителя: оттуда же при первой настройке берутся айди своих,
поэтому «немой» режим не мешает установке. `/whoami` работает только для тех,
кто уже в белом списке.

**Один запрос к модели на сообщение.** Разбор и категоризация делаются вместе,
а не двумя обращениями. При 15–20 сообщениях в день это несколько процентов
бесплатного дневного лимита.

## Локальные проверки

Код Apps Script — обычный JavaScript, поэтому его можно прогонять на Node без
развёртывания. В `tests/` лежит эмуляция среды (таблица, свойства, кэш, HTTP) и
три набора проверок.

```bash
node tests/run_all.js
```

- `check_all.js` — синтаксис каждого файла и вызовы необъявленных функций;
- `test_parser.js` — запасной разбор текста и словарь категорий (26 случаев);
- `test_integration.js` — весь путь сообщения на моках: текст, несколько трат в
  одном сообщении, очередь уточнений, голос, чеки, чеки по ссылке из SMS,
  доходы, возвраты и переводы, кнопки, отчёты, чужой пользователь,
  работа при недоступной модели
  (281 проверка).

Проверки не ходят в сеть и ничего не пишут в реальную таблицу — Gemini и
Telegram подменены заглушками.

Прогонять их стоит после любой правки кода, до того как заливать его в
Apps Script.

## Частые доработки

**Новая категория или ключевое слово** — правится в таблице, лист «Категории».
Код трогать не нужно.

**Другая базовая валюта** — лист «Настройки», строка «Базовая валюта» плюс
курсы. Уже записанные строки не пересчитываются: расход был по тогдашнему курсу.

**Новое слово-маркер дохода** — `INCOME_WORDS_` в `04_TextParser.gs` (разбор
без модели) и правила в `expenseParsingRules_` (`03_Gemini.gs`). Категории
доходов при этом трогать не нужно: они в таблице, лист «Категории доходов».

**Другая модель Gemini** — лист «Настройки», строки «Модель для медиа» и
«Модель для текста». Перекрывают значения по умолчанию из `00_Config.gs`.

**Плохо читаются чеки конкретной сети** — промпт в `03_Gemini.gs`, функция
`geminiParseReceipt_`.

**Ссылки на чеки нового сервиса** — `12_Links.gs`. Общий путь (PDF, картинка,
текст страницы) работает и без доработок, но у сервисов цифровых чеков страница
обычно пустая: содержимое рисуется скриптом уже в браузере. Тогда нужен
адаптер — их три и они устроены одинаково:

1. Открыть ссылку в браузере, во вкладке «Сеть» найти запрос, возвращающий чек
   таблицей (JSON), либо посмотреть, не вшиты ли данные в саму страницу.
2. Добавить проверку домена в `knownServiceReceipt_` и функцию вида
   `<сервис>Receipt_`, которая по адресу страницы соберёт адрес этих данных.
3. Написать `<сервис>ToReceipt_` — перевод полей сервиса в тот же вид, в каком
   чек отдаёт модель (`total`, `datetime`, `store`, `items`, `readable`).

Числа при этом берутся готовыми, а модель переводит названия и выбирает
категорию (`geminiEnrichReceipt_`). Если адаптер вернёт `null`, ссылка пойдёт
общим путём, поэтому сломать разбор он не может.

## Мини-приложение (необязательно)

Кроме чата у бота есть страница со сводкой за месяц: графики по дням, разбивка
по категориям, список записей. Она живёт на Vercel рядом с посредником
(`proxy/public/index.html`), а данные берёт из таблицы через тот же адрес
Apps Script — с проверкой подписи, которую телеграм выдаёт мини-приложению.
Пароля не нужно: подпись считается по токену бота, а он есть только на стороне
Google, поэтому чужой человек, открывший ту же страницу, не увидит ничего.

Чтобы включить: разверните `proxy` на Vercel, впишите адрес страницы в
свойство скрипта `MINIAPP_URL` и запустите функцию `setMiniAppButton` — рядом
с полем ввода в чате появится кнопка «Бюджет». Без этого свойства всё
остальное работает как обычно, просто кнопки не будет.

## Обновления

Код живёт копией в проекте каждой семьи, поэтому правки в этом репозитории
сами по себе до чужих установок не доезжают. Чтобы люди хотя бы узнавали
о новых версиях, бот следит за ними сам.

Раз в неделю (`weeklyUpdateCheck`, триггер ставится при первичной настройке)
бот скачивает `dist/version.json` и сравнивает с `BOT_VERSION` в своём коде.
Версия новее — пишет, что изменилось, и по кнопке присылает файл с новым
кодом и три шага: открыть редактор, выделить всё, вставить. Об одной и той же
версии напоминает один раз. Проверить вручную — `/obnovit`.

**Пишет одному человеку.** Заменить код может только владелец таблицы —
у остальных доступа к редактору нет, и уведомление для них было бы поводом
для беспокойства без возможности что-то сделать. Кому писать, задаётся
настройкой «Кто обновляет бота»; не задана — первый из разрешённых айди.

**А когда обновление встало, бот сам рассказывает всем**, что появилось
нового: заметив при очередном сообщении, что `BOT_VERSION` выросла с прошлого
запуска, он рассылает список изменений по всем разрешённым. Так жена узнаёт
о новых возможностях, не читая переписку мужа с ботом.

Своя ветка разработки живёт через свойство скрипта `UPDATE_SOURCE`: укажите
адрес своего форка, и бот будет следить за ним.

**Почему бот не ставит обновление сам.** Пробовали. Apps Script не выдаёт
скрипту право переписывать собственный код: разрешение `script.projects`
в манифесте остаётся просьбой, а `ScriptApp.getOAuthToken()` возвращает токен
без него — Google выдаёт разрешения по тому, что видит через встроенные
сервисы, а для управления кодом такого сервиса нет. Проверено на живой
установке: `ACCESS_TOKEN_SCOPE_INSUFFICIENT` при `projects.updateContent`.
Обойти можно отдельным проектом Google Cloud, но тогда установка для обычной
семьи вырастает вдвое — полминуты ручной работы раз в месяц того не стоят.

**Как выпускать версию:** поднять `BOT_VERSION` в `00_Config.gs`, добавить
раздел в `CHANGELOG.md` — `node tools/build.js` соберёт из этого
`dist/version.json` и откажется собирать, если раздела нет.

## Резервная копия

Копия проекта уезжает в репозиторий сама — последним шагом
`node tools/deploy.js`. Если гитхаб в этот момент недоступен, выкатка не
срывается: код уже в облаке, а копию можно догнать потом одной командой
`git push`. Не нужна — поставьте `"backup": false` в `.deploy.json`.

Что где хранится и что при чём теряется:

| Что | Где живёт | Переживёт утрату ноутбука |
|---|---|---|
| Код бота | Apps Script + GitHub | да |
| Тесты, документация, посредник | GitHub | да |
| Записи о расходах | Google-таблица | да |
| Токен бота, ключ Gemini, ID таблицы | свойства скрипта Apps Script | да |
| `WEBHOOK_SECRET` посредника | переменные Vercel | да |
| `proxy/.env.local`, `.clasp.json`, `.deploy.json` | только на компьютере | **нет**, и это нарочно |

Секреты в копию не идут: репозиторий приватный, но пароли в хранилище кода —
плохая привычка. Единственный файл, который придётся создать заново, —
`proxy/.env.local`; его содержимое всегда можно посмотреть в настройках проекта
на Vercel.

**Восстановление на новом компьютере:**

```bash
git clone <адрес вашего репозитория>
cd family-budget
npm install -g @google/clasp   # если ещё не стоит
clasp login                    # тем же гугл-аккаунтом
cp .clasp.json.example .clasp.json     # и вписать идентификатор скрипта
cp .deploy.json.example .deploy.json   # и вписать идентификатор развёртывания
node tests/run_all.js          # убедиться, что всё на месте
```

Идентификаторы скрипта и развёртывания в репозиторий не попадают: у каждой
установки они свои. Первый виден в адресе редактора Apps Script, второй
покажет `clasp deployments`. Для правок посредника понадобится ещё
`proxy/.env.local` со строкой `WEBHOOK_SECRET=<значение из Vercel>`.

## Важно при обновлении кода

Apps Script отдаёт телеграму **опубликованную** версию, а не ту, что открыта в
редакторе. После правки: «Начать развёртывание» → «Управление развёртываниями» →
карандаш → «Версия: Новая версия» → «Развернуть». Адрес не меняется, вебхук
переустанавливать не нужно.
