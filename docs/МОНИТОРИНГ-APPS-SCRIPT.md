# Мониторинг Google Apps Script — справка

Как посмотреть, чем занят Apps Script, сколько он съедает бесплатных лимитов
и не упирается ли во что-нибудь. Составлено 23.08.2026 по результатам аудита
аккаунта `ambezrukov@gmail.com`.

---

## 1. Где что смотреть

Четыре страницы, всё остальное — от лукавого:

| Страница | Адрес | Что показывает |
|---|---|---|
| Все проекты | `script.google.com/home/all` | полный список, включая привязанные к таблицам |
| Мои выполнения | `script.google.com/home/executions` | журнал запусков всех проектов: функция, тип, длительность, статус |
| Мои триггеры | `script.google.com/home/triggers` | что запускается по расписанию и как часто, плюс частота ошибок |
| Выполнения одного проекта | `script.google.com/home/projects/<scriptId>/executions` | то же, но по конкретному проекту |

Журнал хранится **7 дней**. Готового счётчика «сколько квоты осталось» у Google
нет — расход считается вручную по журналу.

---

## 2. Лимиты, которые имеют значение

Для личного аккаунта (gmail.com):

| Лимит | Значение | Чем грозит |
|---|---|---|
| Время работы триггеров | **90 минут в сутки** | триггеры перестают запускаться до конца суток |
| Время одного запуска | **6 минут** | запуск обрывается на середине работы |
| Запросы в интернет | 20 000 в сутки | обычно недостижимо |

Три вещи, которые важно понимать:

1. **Квоты считаются на аккаунт, а не на проект.** Все скрипты одного
   пользователя делят один лимит. Новый проект своей квоты не добавляет.
2. **Вебхуки (`doPost` веб-приложения) в 90-минутную квоту не входят.** Она
   только про триггеры. Бот на вебхуке квоту триггеров не расходует вообще.
3. **Шесть минут на запуск не снимаются деньгами.** На платном Google Workspace
   этот лимит такой же. Workspace поднимает суточные квоты (триггеры до 6 часов,
   запросы до 100 000), но не длительность одного запуска.

---

## 3. Как посчитать расход

Формула простая:

```
расход в сутки = (86400 / интервал_триггера_в_секундах) × средняя_длительность
```

Пример: триггер каждые 5 минут → 288 запусков в сутки. Если средний запуск
2,2 секунды, это 634 секунды ≈ **10,6 минуты** из 90.

Среднюю длительность берут из журнала выполнений: открыть «Мои выполнения»,
собрать пару сотен строк и усреднить по каждому проекту. Разброс важен не
меньше среднего — если максимум приближается к 360 секундам, проект уже
касается шестиминутного потолка.

Ориентир по интервалам (при среднем запуске в 2 секунды):

| Интервал | Запусков в сутки | Расход |
|---|---|---|
| каждую минуту | 1440 | ~48 мин — половина квоты |
| каждые 5 минут | 288 | ~10 мин |
| каждые 10 минут | 144 | ~5 мин |
| раз в час | 24 | меньше минуты |

## 5. Проверка перекрытия двух «бюрошных» проектов

Возник вопрос: два разных проекта каждые пять минут крутят функцию с одинаковым
именем `checkNewStatements` — не дубль ли это. Проверено по коду.

**Дубля нет, но перекрытие есть.**

| | Скачивание и обработка выписок Бюро | Финансы Бюро 2026 |
|---|---|---|
| Что ищет в почте | `from:no-reply@alfabank.ru` + тема с **конкретным счётом** `...0078` | `from:no-reply@alfabank.ru` за 7 дней, **любая** тема «Выписка по счёту» |
| Куда пишет | таблица **«Сводная выписка»** | таблица **«Финансы Бюро 2026»** |
| Комментарий в коде | — | `// ID НОВОЙ таблицы` |
| Защита от таймаута | нет | есть: `MAX_RUNTIME_MS = 4.5 мин` |
| Размер | 1361 строка, 27 функций | 2403 строки, 69 функций |

То есть оба проекта каждые пять минут читают **один и тот же почтовый ящик**, и
второй обрабатывает в том числе тот же счёт, что первый, — просто раскладывает
в другую, новую таблицу. Обе таблицы обновлялись в ночь на 23 августа с разницей
в три минуты, то есть работают оба.

Похоже, «Финансы Бюро 2026» — преемник старого проекта, а старый остался включён.
Если таблица «Сводная выписка» больше не нужна, отключение старого триггера
освободит **7,4 минуты в сутки** (8% квоты). Но это решение по существу, а не
техническое: проверять надо не код, а нужна ли сама таблица.

Отдельно стоит отметить: у проектов есть общие по имени функции
(`addTransactionsSmart`, `copyStyleOptimized`, `findInsertIndexInMemory`) —
код копировался между ними. Правки в одном месте в другое не попадут.

## 6. Приёмы, которые пригодились

**Как узнать scriptId привязанного скрипта.** Скрипты, привязанные к таблице,
не видны ни в Google Drive (поиск по `mimeType=application/vnd.google-apps.script`
их не находит), ни через `clasp list` — только standalone. Но на странице
«Мои триггеры» идентификаторы лежат в разметке: в атрибуте `jsdata` в виде
`oc5Rdd;<scriptId>;<номер>`. Достаются одной строкой в консоли браузера:

```js
[...document.querySelectorAll('[jsdata]')]
  .map(e => (e.getAttribute('jsdata').match(/oc5Rdd;([-\w]{40,})/) || [])[1])
  .filter(Boolean)
```

**Как прочитать код проекта не открывая редактор.** Токен `clasp` (лежит в
`~/.clasprc.json`) имеет права `script.projects` — этого хватает:

```bash
curl -H "Authorization: Bearer $TOKEN" \
     https://script.googleapis.com/v1/projects/<scriptId>/content
```

Прав `script.processes` у этого токена нет, поэтому журнал выполнений через API
недоступен — только через веб-интерфейс.

**Защита от шестиминутного обрыва.** Приём из «Финансы Бюро 2026», который стоит
повторять везде, где обрабатываются большие объёмы:

```js
const startedAt = Date.now();
const MAX_RUNTIME_MS = 4.5 * 60 * 1000;
// ... внутри цикла:
if (Date.now() - startedAt > MAX_RUNTIME_MS) return;  // выходим штатно
```

Работа делится на порции, позиция запоминается в `PropertiesService`, следующий
запуск продолжает с неё.

## 7. Что проверять регулярно

Раз в месяц, минут пять:

1. «Мои триггеры» — нет ли триггеров у проектов, которыми уже не пользуетесь,
   и какова частота ошибок (норма — 0%).
2. «Мои выполнения» — нет ли статусов «Время ожидания истекло» и не растёт ли
   средняя длительность.
3. Пересчитать расход по формуле из раздела 3, если добавились новые триггеры.

Тревожные признаки: расход перевалил за 60 минут в сутки; появились обрывы по
таймауту; частота ошибок у триггера выше нуля.
