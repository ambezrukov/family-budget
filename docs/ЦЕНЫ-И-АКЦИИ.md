# Файлы цен и акций израильских сетей — план на будущее

Черновик плана, а не задача в работе. Всё, что здесь написано, проверено
вживую 23.08.2026 с домашней машины (израильский адрес). Команды в примерах
рабочие — их можно повторить.

Повод: сервис [sodasal.co.il](https://sodasal.co.il) («סוד הסל») подбирает
самую выгодную продуктовую корзину по сетям Израиля. Встроить его в бота
нельзя — публичного API нет, условия использования запрещают автоматические
запросы, сайт отдаёт 403 всему, что приходит из дата-центров (та же история,
что с чеками «Рами Леви», см. память `rami-levy-cloudflare-block`). Зато
выяснилось, на чём он работает: на открытых данных, которые доступны и нам
напрямую.

---

## 1. Что это за данные

По израильскому закону о прозрачности цен (חוק לקידום התחרות בענף המזון,
2014) каждая торговая сеть от трёх магазинов обязана публиковать в открытом
доступе цены, акции и список филиалов — отдельным файлом на каждый филиал,
в формате XML, минимум раз в сутки. Это не чья-то база и не результат
парсинга витрин: это официальная публикация самих сетей.

Пять типов файлов:

| Тип | Что внутри | Как часто |
|---|---|---|
| `PriceFull` | полный прайс филиала — все товары | раз в сутки (ночью) |
| `Price` | только изменения цен с прошлой выгрузки | в течение дня, каждый час |
| `PromoFull` | все действующие акции филиала | раз в сутки |
| `Promo` | изменения акций | в течение дня |
| `Stores` | список филиалов сети с адресами | раз в сутки |

Имя файла устроено одинаково у всех:

```
PriceFull7290058140886-001-046-20260823-121500.gz
         └─ChainID───┘ └┬┘ └┬┘ └──дата──┘└время┘
                    SubChain  StoreID
```

`ChainID` — 13-значный код сети (он же её штрихкодовый префикс). Например
`7290027600007` — Шуферсаль, `7290058140886` — Рами Леви.

## 2. Где лежит: три семейства порталов

Единого государственного хранилища нет — на gov.il только список ссылок на
сайты сетей (страница `cpfta_prices_regulations`, отдаётся скриптом, обычным
запросом не читается). На практике порталов три вида.

### 2.1. Cerberus — общий портал (большинство сетей)

`https://url.publishedprices.co.il` — площадка компании NCR, которой
пользуются многие сети. Нужен логин, но он **публичный и общеизвестный**:
имя пользователя — название сети, пароль обычно пустой.

Проверено 23.08.2026 (все восемь входят, файлы отдаются):

| Логин | Пароль | Сеть | PriceFull-файлов |
|---|---|---|---|
| `RamiLevi` | пусто | רמי לוי | 296 |
| `TivTaam` | пусто | טיב טעם | 54 |
| `yohananof` | пусто | יוחננוף | 66 |
| `osherad` | пусто | אושר עד | 48 |
| `doralon` | пусто | דור אלון | 156 |
| `Keshet` | пусто | קשת טעמים | 30 |
| `freshmarket` | пусто | פרש מרקט | 53 |
| `politzer` | пусто | פוליצר | 8 |
| `SalachD` | `12345` | סאלח דבאח | 6 |

Как забрать файлы (проверенная последовательность):

```bash
# 1. Взять cookie-сессию и csrf-токен (лежит в <meta name="csrftoken">)
curl -s -c cj.txt https://url.publishedprices.co.il/login -o login.html

# 2. Войти
curl -s -b cj.txt -c cj.txt -X POST https://url.publishedprices.co.il/login/user \
     -d "r=&username=RamiLevi&password=&csrftoken=ТОКЕН"

# 3. Список файлов — JSON, с поиском по имени
curl -s -b cj.txt -X POST https://url.publishedprices.co.il/file/json/dir \
     -H "X-Requested-With: XMLHttpRequest" \
     -d "sEcho=1&iDisplayStart=0&iDisplayLength=300&sSearch=PriceFull&cd=%2F&csrftoken=ТОКЕН2"

# 4. Скачать
curl -s -b cj.txt -o f.gz https://url.publishedprices.co.il/file/d/ИМЯ_ФАЙЛА
```

Важно: `csrftoken` меняется на каждой странице — после входа брать новый из
ответа. Ответ листинга — JSON с полями `fname`, `size`, `time`.

### 2.2. Портал сети на своём домене (Шуферсаль и похожие)

`https://prices.shufersal.co.il` — без логина. Список — обычная HTML-таблица,
сами файлы лежат в Azure и **выдаются по ссылке с подписью, живущей около
часа** (`?sv=...&sig=...&se=2026-08-23T10:12:01Z`). То есть ссылку нельзя
сохранить впрок — сначала листинг, сразу за ним загрузка.

Фильтр по типу файла — через отдельный адрес:

```
https://prices.shufersal.co.il/FileObject/UpdateCategory?catID=2&storeId=0
# catID: 1=Price, 2=PriceFull, 3=Promo, 4=PromoFull, 5=Stores
# storeId=0 — все филиалы
```

Так же устроены `prices.super-pharm.co.il` и `prices.carrefour.co.il`
(Carrefour = бывшая «Мега»/«Йенот Битан»).

### 2.3. Bina Projects — проще всех

`https://<сеть>.binaprojects.com/MainIO_Hok.aspx` отдаёт готовый JSON со
списком файлов, без логина вообще. Проверено на `kingstore` и `maayan2000`.

```json
[{"FileNm":"Price7290058108879-000-339-20260823-120518.GZ",
  "Store":"339 יפו תלאביב מכללה","TypeFile":"מחירים","DateFile":"12:05 23/08/2026"}]
```

### 2.4. Чего не хватает

`matrixcatalog.co.il` (Виктори, Махсаней ха-Шук и др.) 23.08.2026 не отвечал
вовсе. Готовый обзор кто где публикует — в открытом проекте
[OpenIsraeliSupermarkets/israeli-supermarket-scarpers](https://github.com/OpenIsraeliSupermarkets/israeli-supermarket-scarpers)
(Python, поддерживает Шуферсаль, Рами Леви, Карфур, Виктори, Тив Таам,
Йохананоф, Дор Алон, Супер-Фарм, Кофикс и другие). Брать оттуда стоит не код,
а список адресов и знание, где что ломается.

## 3. Как это выглядит внутри

### Товар (`PriceFull`)

```xml
<Item>
  <PriceUpdateTime>2025-12-28T14:15:00</PriceUpdateTime>
  <ItemCode>7290000964980</ItemCode>          <!-- штрихкод -->
  <ItemType>1</ItemType>                       <!-- 1=штрихкод, 0=внутренний код -->
  <ItemName>אבוקדו</ItemName>
  <ManufactureName>קטיף.</ManufactureName>
  <ManufactureCountry>IL</ManufactureCountry>
  <UnitQty>קילוגרם</UnitQty>
  <Quantity>1.00</Quantity>
  <UnitOfMeasure>1קילוגרם</UnitOfMeasure>
  <bIsWeighted>1</bIsWeighted>                 <!-- весовой товар -->
  <ItemPrice>15.90</ItemPrice>
  <UnitOfMeasurePrice>15.90</UnitOfMeasurePrice>
</Item>
```

**Категории товара в файле нет** — ни «молочное», ни «бытовая химия».
Есть только название, производитель и объём. Это ключевое ограничение:
автоматическую категоризацию покупок из этих файлов не построить, нужен
свой слой (эвристика по названию или разовая разметка моделью).

### Акция (`PromoFull`)

```xml
<Promotion>
  <PromotionID>0001422248</PromotionID>
  <PromotionDescription>קנה חול חתולים 10 ליטר קבל חול 6 ליטר</PromotionDescription>
  <PromotionStartDateTime>2026-08-11T00:00:00</PromotionStartDateTime>
  <PromotionEndDateTime>2026-08-31T23:59:00</PromotionEndDateTime>
  <ClubID>0</ClubID>                           <!-- 0 = для всех, иначе клуб -->
  <MinNoOfItemOffered>10</MinNoOfItemOffered>
  <Groups><Group><PromotionItems>
    <PromotionItem>
      <ItemCode>5705833080407</ItemCode>
      <MinQty>1</MinQty>
      <DiscountedPrice>89.90</DiscountedPrice>
    </PromotionItem>
  </PromotionItems></Group></Groups>
</Promotion>
```

Акции — самая грязная часть данных: условия описаны текстом, зависят от
клуба, минимальной суммы, купонов и комбинаций товаров. Честно посчитать их
трудно, и sodasal об этом прямо предупреждает.

### Филиалы (`Stores`)

```xml
<Store><StoreID>001</StoreID><StoreName>מרכז</StoreName>
       <Address>הרצל, 15</Address><City>3000</City><ZipCode>9342110</ZipCode></Store>
```

Внимание на кодировки: `PriceFull` у Шуферсаля и Рами Леви — UTF-8 с BOM,
а `Stores` Рами Леви — **UTF-16**. Встречается и Windows-1255. Читать вслепую
как UTF-8 нельзя, иначе на выходе кракозябры.

## 4. Сколько это весит (замерено)

| Что | Сжатый | Распакованный | Позиций |
|---|---|---|---|
| `PriceFull` Шуферсаль, один филиал | 325 КБ | 5,3 МБ | 6 535 |
| `PriceFull` Рами Леви, один филиал | 1,1 МБ | ~11 МБ | 13 093 |
| `PromoFull` Рами Леви, один филиал | 358 КБ | 8,8 МБ | 2 579 акций |
| `Price` (только изменения) | 0,7 КБ | 3,5 КБ | единицы |
| `Stores`, вся сеть | — | 38 КБ | все филиалы |

Сводный справочник из двух филиалов (Шуферсаль + Рами Леви): **16 637
уникальных товаров**, JSON «код → название, объём, единица» — **1,33 МБ**
(278 КБ в сжатом виде). Только «код → название» — 0,89 МБ.

Вывод по объёмам: качать всю страну (десятки сетей × сотни филиалов =
гигабайты в сутки) в наших рамках бессмысленно и не нужно. Три-четыре
«своих» магазина — это единицы мегабайт в неделю, вполне подъёмно.

## 5. Что из этого нам действительно полезно

По убыванию отношения «польза / трудозатраты».

### A. Справочник магазинов (`Stores`) — дёшево и сразу полезно

Все филиалы всех сетей с адресами — это 40 КБ на сеть. Даёт:

- узнавание магазина в строке банковской выписки («רמי לוי חיפה» → сеть
  «Рами Леви», филиал, адрес) и автоматическую категорию без вопросов
  к человеку;
- статистику «где мы вообще покупаем»;
- заполнение справочника магазинов в таблице вместо ручного ввода.

Это ложится на уже существующий механизм категоризации по магазину
(`05_Categorizer.gs`, `23_Categorize.gs`), а не заменяет его.

### B. Отчёт «сколько можно было сэкономить»

По позициям уже записанного чека посмотреть, сколько та же корзина стоила
в тот день в других сетях. Не планирование покупки (это делает sodasal),
а взгляд назад — что естественно для бота учёта.

Слабое место: **сопоставление позиций**. Бот сейчас достаёт из чека только
названия, кодов товаров не извлекает (проверено по `03_Gemini.gs`), а в
израильских чеках штрихкод печатается не всегда. Без кода сопоставление
нечёткое. Первый шаг здесь — научить разбор чека вытаскивать код товара
там, где он есть; тогда стыковка становится точной.

### C. Нормализация позиций чека

Сокращения на иврите из чека («חלב תנובה 3%» в урезанном виде) превращать
в нормальное название, объём и единицу измерения. Полезно для будущих
отчётов «что покупаем», для поиска по истории и как основа для B.

### D. Чего делать не нужно

Свой движок сравнения корзин по всем сетям с учётом акций, клубов, доставки
и времени дороги. Это отдельный продукт, им уже занимается sodasal — и
занимается всерьёз, судя по FAQ. Наш проект про учёт, а не про планирование.

## 6. Как автоматизировать в наших рамках

Рамки прежние: бесплатно, без своего сервера, хранилище — Google-таблица,
исполнение — Apps Script.

**Хорошая новость:** порталы цен, в отличие от sodasal и чеков «Рами Леви»,
**открыты для облаков** — проверено 23.08.2026 запросом снаружи Израиля,
и `prices.shufersal.co.il`, и `url.publishedprices.co.il` отвечают. Значит
Apps Script, скорее всего, сможет ходить туда сам. Проверить это одним
запросом до того, как писать код.

Разделение труда — «тяжёлое локально, лёгкое в облаке»:

| Что | Где | Почему |
|---|---|---|
| Разбор 5–11 МБ XML | локально, скрипт в `tools/` (Node) | в Apps Script это риск упереться в 6-минутный лимит |
| Готовый компактный JSON-справочник | файл на Google Drive рядом с таблицей | 1–2 МБ читаются скриптом без труда |
| Ежедневное обновление мелочей (`Stores`, `Price`) | Apps Script по триггеру | файлы маленькие, XmlService справится |
| Поиск по справочнику | Apps Script + `CacheService` | словарь в память на 6 часов, дальше мгновенно |

Технические заметки на будущее:

- `Utilities.ungzip(blob)` в Apps Script есть — распаковка `.gz` штатная.
- `XmlService.parse()` на файле в 5 МБ — рискованно; надёжнее разбирать
  построчно регулярным выражением по `<Item>…</Item>` порциями, сохраняя
  позицию в `PropertiesService` между запусками.
- Хранить справочник в `PropertiesService` нельзя (9 КБ на значение,
  500 КБ на скрипт), в `CacheService` — только кусками (100 КБ на значение).
  Правильное место — файл на Диске.
- Ссылки Шуферсаля подписаны и живут около часа: сначала листинг, сразу
  за ним загрузка, впрок не сохранять.
- Обновлять справочник товаров раз в неделю, `Stores` — раз в месяц:
  ассортимент и адреса меняются медленно, а цены нам нужны только на дату
  покупки.

Порядок работ, если возьмёмся: сначала A (справочник магазинов — самостоятельная
польза, минимум кода), потом извлечение кода товара из чека, потом C, и только
после этого B, у которого без первых трёх нет опоры.

## 7. Риски и ограничения

1. **Категорий товаров в файлах нет** — автокатегоризация покупок из них
   не выводится, нужен свой слой поверх.
2. **Кодов товаров в чеках может не быть** — тогда сопоставление остаётся
   нечётким, по названию.
3. **Качество данных.** Сети публикуют по закону, но с ошибками: пустые
   поля, `לא ידוע` вместо производителя и единицы, устаревшие цены. Сам
   sodasal предупреждает, что расхождение с кассой означает ошибку в
   официальной публикации сети.
4. **Порталы ломаются.** Часть сетей периодически недоступна, часть
   закрыта от запросов из-за границы, форматы у всех слегка разные.
   Любая автоматика здесь требует терпимости к сбоям и не должна ронять
   основную работу бота.
5. **Юридически** данные открытые и использовать их можно; ограничение
   на автоматические запросы было в условиях sodasal — к самим порталам
   сетей оно не относится. Но вести себя вежливо (несколько файлов в
   неделю, а не постоянный перебор) — правильно и практично.
